0:30–2:00

2. Caso y arquitectura

Diagrama
Dices

El sistema permite el CRUD de usuarios, roles y permisos, y tiene dos reglas que deben ocurrir automáticamente con eventos: cuando se crea un usuario, se le asigna un rol por defecto; y cuando se elimina un rol, se les quita a todos los usuarios que lo tenían.

PantallaRecorrer el diagrama con el mouse, de izquierda a derecha.
Dices

Postman llama al BFF en Spring Boot, que corre como contenedor Docker en Azure Container Apps. El BFF orquesta las funciones serverless: usuarios y permisos con REST, roles y asignaciones con GraphQL. Cada función guarda el cambio en Oracle y publica un evento en un topic de Azure Event Grid.

PantallaSeñalar el recuadro de Event Grid y luego el de las funciones de la derecha (en verde, lo nuevo).
Dices

Event Grid entrega cada evento a las funciones suscritas, según el filtro de cada suscripción. Para esta evaluación agregué dos procesadores, en verde: el de rol por defecto escucha Usuario.Creado, y el de rol eliminado escucha Rol.Eliminado. Los procesadores publican eventos nuevos, que son las flechas punteadas. Además, la auditoría guarda todos los eventos y las notificaciones avisan a cada usuario afectado.

3. Código

VS Code
PantallaBffController.java, línea 35, y bajar al método reenviar.
Dices

Este es el BFF en Spring Boot. Cada ruta reenvía la petición a la función serverless que corresponde y devuelve la respuesta en JSON.

PantallaUsuariosFunction.java, línea 200 → ProcesadorRolPorDefectoFunction.java, líneas 35, 61 y 93.
Dices

Al crear un usuario, la función publica Usuario.Creado. Este procesador tiene la anotación EventGridTrigger, así que Azure lo ejecuta cuando llega ese evento. Busca el rol USUARIO, lo inserta en USUARIOS_ROLES y publica UsuarioRol.Asignado. Si Event Grid reintenta la entrega, no se duplica: el usuario ya tiene el rol y no hace nada.

PantallaRolesGraphQLFunction.java, líneas 250 y 272 → ProcesadorRolEliminadoFunction.java, líneas 46, 77 y 67.
Dices

Al eliminar un rol, la función GraphQL lee su nombre, lo borra y publica Rol.Eliminado. El procesador de rol eliminado busca a los usuarios que lo tenían, borra esas asignaciones en una transacción y publica un UsuarioRol.Revocado por cada usuario.

Pantallasemana9_eventos.sql, línea 18.
Dices

Para que esa limpieza la haga el componente de eventos y no la base de datos, quité el borrado en cascada de la llave foránea. Es consistencia eventual: por un par de segundos pueden quedar asignaciones de un rol que ya no existe, pero no se ven, porque las consultas cruzan con la tabla de roles.
